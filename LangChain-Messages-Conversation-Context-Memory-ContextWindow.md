# 2. Messages in LangChain

The video explains three important message types:

### SystemMessage

Used to give **instructions to the LLM**.

For example:

> "Act as an experienced Python trainer."

or

> "Act as a cardiologist with 20 years of experience."

The system message influences **how the LLM should behave**.

### HumanMessage

Represents the message/question coming from the user.

Example:

> "What is Python?"

### AIMessage

Represents the response generated by the LLM.

So the basic flow is:

```text
SystemMessage
      ↓
HumanMessage
      ↓
LLM
      ↓
AIMessage
```

# 4. The "Gajini" example — understanding stateless LLMs

This is probably the most important conceptual example in the video.

Suppose you tell the LLM:

> "Hello, my name is Sudha."

It responds:

> "Hello Sudha!"

Then you ask:

> "What is my name?"

The LLM may respond:

> "I don't know your name."

Why?

Because the second request did **not contain the first conversation**.

The LLM doesn't automatically remember the previous request.

This behavior is called:

### **Stateless**

The instructor compares it to **HTTP**, which is also traditionally described as stateless: each request is independent unless some mechanism is added to maintain the session.

### LLM

### ChatGPT

ChatGPT is an **application built around LLMs**.

The application can implement things such as:

- Conversation history
- Memory
- Context management

# 6. LLM vs Application — very important distinction

Think about this:

```text
                Application
              ┌───────────────┐
              │ ChatGPT       │
              │ Memory        │
              │ Context       │
              │ Tools         │
              └───────┬───────┘
                      │
                      ▼
                   LLM
```

The LLM is responsible for generating the response.

The **application is responsible for deciding what information to send to the LLM**.

This distinction is extremely important when building Agentic AI applications.

# 7. What is "Context"?

The instructor gives this definition:

> **Context is information provided to the model that helps it understand and process the current request.**

For example:

First:

```text
Human: My name is Sudha.
AI: Nice to meet you, Sudha.
```

Then:

```text
Human: What is my name?
```

If we send only:

```text
"What is my name?"
```

the LLM doesn't know.

But if we send:

```text
Human: My name is Sudha.
AI: Nice to meet you, Sudha.
Human: What is my name?
```

then the LLM has the necessary **context**.

# 8. How did the instructor implement memory without LangChain?

This is a particularly useful part for your learning.

He creates a Python list:

```python
messages = []
```

Then stores the conversation inside it.

For example:

```text
messages
   │
   ├── SystemMessage
   ├── HumanMessage
   ├── AIMessage
   ├── HumanMessage
   ├── AIMessage
   └── ...
```

Every time the user sends a message:

1. Add the HumanMessage to the list.
2. Send the entire relevant list to the LLM.
3. Receive the AIMessage.
4. Add the AIMessage to the list.
5. Continue.

The important part is:

> **The LLM isn't remembering the conversation. The application is storing it and sending it again.**

The instructor explicitly demonstrates this approach using ordinary Python list operations such as `append()`. :chatgpt-content-reference{index="3"}

# 11. Temporary memory vs permanent memory

This is another important distinction.

The Python list:

```python
messages = []
```

is stored in the program's memory/RAM.

Therefore:

```text
Application running
       ↓
messages list exists
       ↓
Conversation remembered
```

But when the application terminates:

```text
Application stops
       ↓
Python list disappears
       ↓
Conversation history is lost
```

So this is **temporary memory**, not persistent memory.

For long-term memory, you would need something like:

```text
Database
Vector database
File
Cloud storage
etc.
```

The instructor explicitly describes the Python list approach as temporary rather than persistent memory.

# 13. The BIG problem with sending the entire history

Now the instructor introduces the next major concept.

Imagine:

```text
Message 1
Message 2
Message 3
...
Message 1,000
```

If you send the entire history every time, the request becomes huge.

For request #1000, you're potentially sending:

```text
Message 1
Message 2
Message 3
...
Message 999
Message 1000
```

again.

This creates several problems.

### 1. Cost

More input tokens → more token usage → potentially higher cost.

### 2. Latency

More information must be processed.

Therefore:

```text
More context
     ↓
More processing
     ↓
Higher latency
```

### 3. Context-window limitation

Eventually you may reach the model's maximum context size.

The instructor therefore emphasizes that **effective context management is important**. :chatgpt-content-reference{index="5"}

# 14. Context Window

This is the next major concept.

### Context window = maximum amount of information the model can consider at one time.

The unit used is:

## **Tokens**

Not:

- pages
- lines
- words

but **tokens**.

For example, depending on the tokenizer:

```text
Hello
```

might be one token, while a longer/unusual word could be split into multiple tokens.

So:

> **Token ≠ necessarily one word.**

The instructor also explains that context-window size varies by model. :chatgpt-content-reference{index="6"}

# 15. Context Window vs Context

This distinction is worth memorizing.

### Context

The information supplied to help the LLM answer the current request.

### Context Window

The **maximum amount of information/tokens the model can consider at one time**.

Think:

```text
Context
   ↓
The information you give

Context Window
   ↓
The maximum information the model can handle
```

# 16. What happens when context becomes too large?

If you exceed the model's context window, behavior depends on the model/application.

Potentially:

```text
Old information removed
```

or

```text
Request rejected
```

or another context-management strategy may be used.

The important takeaway is:

> You cannot keep sending unlimited conversation history to an LLM.
